# 6G-DTC-Dynamic-Access KPIs 分析与绘图工作流

为了在频繁调整论文或报告图表排版样式时避免重复进行耗时的系统级通信仿真，本项目的测试和绘图采用了解耦的结构，分为两个核心步骤。

## 1. 整体工作流 (生产者-消费者模式)

### 第一步：仿真跑数据分析 (数据生产者)
**核心脚本**：`tools/plot_kpis_vs_nue.py` 以及 `run_ue_scaling_analysis.py`

- **功能**：调用系统的底层代码环境，执行单星或星座场景下的实际调度仿真。它会扫频测试不同 UE 数量梯度 (例如 25, 50, 75, 100) 下的系统性能表现。
- **输出产物**：会在相应的 `output` 相关的文件夹（如 `output_toronto/jain/output_images_.../`）中生成带有时间戳的 `.csv` 原始数据文件，保存了每种调度算法在测试下所得出的平均频谱效率（Spectral Efficiency, SE）和 Jain's 公平性指数。
- **运行命令示例**：
  ```bash
  python tools/plot_kpis_vs_nue.py --scenario constellation
  ```
  *(注：根据参数也可使用 `--scenario all` 执行全部场景，运行往往需较长时间。)*

### 第二步：精美折线/柱状图出图 (图表消费者)
**核心脚本**：`output_toronto/jain/plot_results.py`

- **功能**：该脚本纯粹用于离线可视化提取。无需重新跑长耗时的仿真，你只需要将脚本代码文件顶部定义好的 `single_csv` 和 `const_csv` 变量值，指向并替换为第一步产生出的最新 `.csv` 文件相对路径即可。
- **图表微调**：此脚本负责高端的格式排版，例如调整论文级别的高级配色（基础方案的暖橘/砖红 vs 我们提出的算法的薄荷绿方案）、柱状体上加以区分的斜线纹理 (`hatch='\\'` 等)、以及图表刻度微调和去重边框设计。
- **输出产物**：它能够极速、瞬间输出供论文直接使用的精美高分辨率 `.png` 图表 (例如 `Constellation_SE_Bar.png`)。

## 2. 核心调度算法实现及指标计算位置

本系统中用于三方性能对比的资源调度算法及其数值分析统计代码深入耦合于核心代码，基于统一的随时间变化的 TTI（传输时间间隔）调度框架。

**主要实现文件路径：** `code/main.py`

### 2.1 底层调度算法逻辑 (PF, MR, RM-DSS)

在 `code/main.py` 的核心仿真运行函数 `run_once` 与 `run_constellation` 的主体资源块循环遍历内。三者依赖一套统一的分块调度架构 (`scheduler_step`)：

- **传统比例公平调度 (Baseline PF)**：
  - *定位注释*：`"Baseline: contiguous-block PF using per-PRB metric"`
  - *实现原理*：使用历史统计到的吞吐量均值（$\bar{R}_{base}$）作为惩罚分母，每次在 TTI 内利用 $\Delta R / \bar{R}$（瞬时可达速率与平均速率的比值）的优先度指标进行贪婪选择，以期在最大化系统吞吐量和照顾弱势信道用户间取得一定的比例平衡。

- **传统最大速率调度 (Baseline MR)**：
  - *定位注释*：和 PF 共用同一套循环逻辑。
  - *实现原理*：相当于禁用了历史吞吐量惩罚衰减（或设置内部配置 `pf_beta = 0`），其决策依据变为纯粹去获取当时刻 $\Delta R$ 最好的信道链路。只追求系统信道容量极大化而不顾虑远端边缘用户的饥饿问题。

- **动态频谱共享算法 (Proposed RM-DSS / RadioMap)**：
  - *定位注释*：`"RadioMap: contiguous-block PF with per-PRB metric"`
  - *实现原理*：引入地理大尺度映射信息，减轻由小尺度衰落和信道状态信息(CSI)反馈的大延迟而带来的时延模糊。它改用提前注入的 `metric_override` 映射地图数据作为预估决策参考度量，显著提高了实际带有延迟约束系统的卫星下行分配性能。

### 2.2 Jain's 公平性指数计算 (Jain's Fairness Index)

同样位于 `code/main.py` 的内部逻辑里，通过嵌套定义的辅助统计函数 `jain(x)` 构建。

- **实现原理**：
  仿真系统在所有 TTI 执行完后，会将积累统计的各类算法关于每台 UE 设备上的平均频谱效率统计列阵记录好（即 `se_ue_base`、`se_ue_mr`、`se_ue_map`），以此带入该公式：
  $$ J(x) = \frac{(\sum_{i=1}^{n} x_i)^2}{n \sum_{i=1}^{n} x_i^2} $$
  返回介于 $0$（极度不公）到 $1$（绝对公平）之间的浮点数值以供 csv 生成调用。
